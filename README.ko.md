# Preset Seed Lab 1.4

기존 Lightroom XMP 씨드를 변주하거나, **여러 프리셋을 믹스매치하거나, 레퍼런스 사진에서 색감·톤을 추정해 XMP 프리셋을 만드는** Windows 데스크톱 앱입니다. 분위기·톤·색감·팔레트·스타일 키워드 44개, 충실도와 변주 폭, 인물·배경 마스크 보정, 토큰·검색 사용량 대시보드를 지원합니다.

## 프리셋 믹스매치 · 로컬 기본 / AI 선택

사이드바의 **프리셋 믹스매치**(Ctrl+5)에서 내 프리셋의 보정값을 조합합니다. 기본값은 **AI 끔**이며 API 키나 인터넷 없이 생성합니다.

1. **XMP 추가**, **폴더 추가**, 끌어다 놓기 또는 **현재 씨드 가져오기**로 2~12개를 등록합니다. 현재 씨드 가져오기는 사용 체크된 씨드를 가져옵니다.
2. 각 행의 비율 슬라이더를 조절합니다. 예를 들어 30과 70은 30%/70%이며, 10과 30은 25%/75%로 환산됩니다. 0은 제외입니다. **같은 비율로**는 모두 동일 비율로 되돌립니다.
3. **톤·색감·질감·커브**별로 **비율대로 섞기**, **기준 프리셋 유지**, 특정 프리셋을 선택합니다. 예: A의 톤과 B의 질감을 가져오고, 색감은 A/B를 30:70으로 혼합합니다. 특정 항목에 쓸 프리셋도 비율이 0보다 커야 합니다.
4. **기준 프리셋**을 고릅니다. 화이트밸런스·카메라 프로필·LUT·마스크·크롭·샤프닝 등 혼합 대상이 아닌 설정은 이 프리셋에서 유지합니다. 서로 다른 프로필이나 마스크를 겹쳐 합성하지 않습니다.
5. 생성 개수는 1~24개입니다. 로컬 첫 결과는 지정 비율 그대로이며, 추가 후보는 **조합 탐색 폭**에 따라 항목별 비율을 조금씩 달리합니다. 0이면 비율을 유지하므로 중복 후보가 제외될 수 있습니다.
6. 선택적으로 **AI로 자연스럽게 섞기 → AI 사용**을 켭니다. 공용 API 키와 모델을 입력하고 원하는 느낌을 메모합니다. AI가 보정값·커브·메모를 보고 항목별 비율을 제안합니다. 사용자가 지정한 항목은 고정하고, 비율대로 섞는 항목에만 적용합니다. 탐색 폭 100에서도 최종 비율의 절반 이상은 사용자가 정한 비율을 유지합니다. 사진은 전송하지 않으며 실제 렌더링에 기반한 조화 평가가 아닙니다.
7. **믹스매치 생성**을 누릅니다. `MixMatch_…` 하위 폴더에 XMP와 `manifest.json`을 저장하고, 결과 상세에 기준 프리셋·항목별 사용 비율·변경값을 표시합니다. 원본 파일은 수정하지 않습니다.

혼합 대상은 톤의 노출·대비·밝은/어두운 영역, 색감의 HSL·채도·토닝/일부 컬러 그레이딩, 질감의 텍스처·클래리티·디헤이즈·그레인, RGB/채널 포인트 커브입니다. 일부 프리셋에 없는 슬라이더는 중립값으로 계산하며, 모두에 없는 필드는 추가하지 않습니다. 색상 각도는 채도를 가중치로 원형 평균합니다. 여러 커브는 입력 밝기 0/64/128/192/255에서 보간한 Y값을 혼합합니다. 한 프리셋의 커브를 지정하면 기존 좌표를 유지하며, 해당 프리셋에 커브가 없으면 기준 커브를 직선으로 중립화합니다. 이는 사진 픽셀을 겹쳐 섞거나 Lightroom의 렌더링을 재현하는 기능이 아닙니다.

현상 버전이 다르거나 컬러/흑백 방식이 다른 프리셋, 지원 범위를 벗어난 값, 섞을 수치가 없는 선택은 API 호출 전에 안내합니다. 프로젝트를 사용하면 등록 파일·비율·기준·항목별 선택·메모·옵션·지난 결과를 저장하고 재실행 때 복원합니다. 이미 프로젝트 안에 있는 파일은 그대로 재사용하며 외부 XMP는 `mix` 폴더로 복사합니다.

AI 설계는 후보 6개당 최대 한 호출(`ceil(개수/6)`)이며 대시보드에 **믹스매치 설계**로 기록됩니다. AI 오류 후 자동으로 로컬 결과를 만들거나 유료 요청을 재시도하지 않습니다. 확인된 사용량과 중지 전 저장된 XMP·혼합 비율은 유지합니다.

## v1.4 변경 사항 · 2026-10-16

화면 디자인과 사용성을 개선하고, 레퍼런스 생성의 수치 검증 오류를 복구하는 버전입니다.

- **커브 오류 복구:** `Curve must be monotonic within 0..255`로 전체 생성이 중단되던 문제를 수정했습니다. 레퍼런스의 5개 Y 좌표가 유한한 숫자이면 0~255로 제한하고, 역순 구간을 인접 평균으로 맞춘 뒤 정수화합니다. X 좌표의 순서는 유지합니다. 모든 점이 같은 높이가 되는 커브는 기본 직선으로 대체합니다. 정상 커브와 씨드의 원본 커브는 그대로 유지합니다. 비감소 제약은 이 앱의 레퍼런스 추정 정책이며, Lightroom의 모든 커브 형식에 대한 제한을 뜻하지 않습니다.
- **수치 보정 내역:** 레퍼런스의 전역·인물·배경 슬라이더가 허용 범위를 벗어나면 범위 안으로 제한합니다. 결과 화면에 자동 보정을 알리고 `manifest.json`의 `repairs`에 레퍼런스 ID·필드·보정 전후 값을, `analysis.txt`에 읽을 수 있는 내역을 남깁니다. 내보내기 중지 후 부분 manifest에도 보존합니다. 이 복구에는 추가 API 호출이 없습니다. 누락된 필드·숫자가 아닌 값·잘못된 사진 ID는 임의로 채우지 않고 해당 단계와 필드를 안내합니다.
- **사진 사전 확인:** 모든 레퍼런스와 적용할 원본 사진을 첫 API 호출 전에 읽고 확인합니다. 파일을 읽는 동안 변경을 막고 등록 시 해시와 비교합니다. 축소한 이미지를 메모리에 보관해 관찰·수치 추정에 같은 사진을 쓰며, 뒤쪽 사진이나 원본 사진의 읽기 실패로 먼저 사용량을 소비하는 문제를 막았습니다.
- **실패 안내:** 잘린 응답·거절·잘못된 JSON·인증/모델 접근/요청 제한/네트워크 오류를 구분해 안내합니다. 실패한 요청을 자동 재전송하지 않으며 확인된 사용량은 유지합니다.

- **새 디자인:** 색상 토큰을 정리하고 버튼·입력란·드롭다운·체크박스·스위치·슬라이더·스크롤바·탭·표·툴팁을 모두 같은 스타일로 다시 그렸습니다. 작은 회색 글자의 대비를 높이고 기본 글자 크기를 키웠습니다. 사이드바에 아이콘을 넣고, 하단 문구가 메뉴 바로 아래 붙던 배치 오류를 고쳤습니다.
- **단계형 화면:** 프리셋 생성과 레퍼런스 화면의 카드에 1–5(6) 단계 번호를 붙였습니다. 슬라이더마다 현재 값과 양 끝의 의미를 표시합니다. AI를 끄면 키·모델·사진 입력이 비활성화되어 로컬 변주라는 점이 보입니다.
- **실행 요약:** 하단 작업 표시줄에 씨드·키워드·후보 수와 예상 API 호출 수를 미리 보여 줍니다. 빠진 입력이 있으면 무엇이 필요한지 알려 줍니다. 생성 버튼은 생성 화면에서만 보입니다.
- **진행 표시:** 진행률 막대와 경과 시간을 표시합니다. 생성 중 창을 닫으면 확인을 받습니다. 중지 버튼은 작업 중에만 보입니다.
- **결과 화면:** 요약 헤더(완료/부분 결과), 후보 목록, 상세 패널로 나눴습니다. 상세 패널은 바뀐 보정값을 한국어 이름(노출, 대비, HSL 색상 · 빨강 등)의 칩으로 보여 주고, 레퍼런스 결과는 인물·배경 보정값을 따로 표시합니다. 행을 더블클릭하거나 **위치 열기**를 누르면 탐색기에서 해당 XMP를 선택합니다.
- **입력 편의:** XMP·사진·폴더를 카드에 끌어다 놓을 수 있습니다. 레퍼런스 사진은 EXIF 회전을 반영한 썸네일로 보입니다. 씨드는 한 번 클릭으로 사용 여부를 바꾸며 **모두 사용/모두 해제**, **선택 삭제**(Delete 키)를 지원합니다. 키워드 칩에 마우스를 올리면 보정 방향(예: 부드러움 ↑ · 대비 ↓)을 보여 주고, 선택 수와 **모두 해제**를 표시합니다. 생성 개수 입력란은 숫자만 받고 범위를 벗어나면 붉게 표시합니다.
- **프로젝트 폴더:** 사이드바의 **프로젝트 → 폴더 지정**으로 작업 폴더를 정합니다. 추가한 씨드 XMP·레퍼런스 사진·원본/분석용 사진·마스크 템플릿을 `seeds`, `references`, `photos`, `masks` 하위 폴더에 복사하고, 목록·사용 체크·키워드·메모·생성 옵션·마지막 결과 폴더를 `seedlab-project.json`에 자동 저장합니다. 경로는 프로젝트 기준 상대 경로라 폴더를 옮겨도 열 수 있습니다. 같은 내용의 파일은 다시 복사하지 않습니다. 결과 기본 위치는 `<프로젝트>\outputs`입니다. 다음 실행 때 마지막 프로젝트를 자동으로 열고 지난 결과도 결과 화면에 다시 보여 줍니다. 기존 프로젝트 폴더를 고르면 그 작업을 열고, 빈 폴더를 고르면 지금 목록을 복사할지 물은 뒤 새 프로젝트를 만듭니다. 목록에서 뺀 항목의 복사본은 프로젝트 폴더에 남습니다. 프로젝트를 지정하지 않으면 목록은 저장되지 않습니다.
- **API 키 공유·저장:** 프리셋 생성과 레퍼런스 화면이 같은 키 입력을 공유합니다. 기본값은 메모리 전용입니다. **이 PC에 키 저장**을 켜면 Windows DPAPI(현재 Windows 계정 범위)로 암호화해 `%LOCALAPPDATA%\PresetSeedLab\api-key.json`에 저장하고 다음 실행에 채웁니다. 다른 계정이나 PC에서는 복호화되지 않으며, 끄면 저장된 키를 즉시 삭제합니다. 키는 프로젝트 폴더·`settings.json`·결과·사용 기록에는 쓰지 않습니다.
- **설정 기억:** 저장 폴더, 모델, 생성 개수, 충실도·변주 폭, AI 사용 여부, 레퍼런스 추출 방식·검색 여부, 창 크기, 마지막 화면, 마지막 프로젝트 경로를 `%LOCALAPPDATA%\PresetSeedLab\settings.json`에 저장합니다. 프로젝트가 열려 있으면 프로젝트의 값이 우선합니다.
- **단축키:** Ctrl+Enter 생성, Ctrl+1–5 화면 이동, Ctrl+O 파일 추가, 대시보드에서 F5 새로고침.
- **대시보드:** 숫자 열을 오른쪽 정렬하고 상태를 색상 배지로 표시합니다. 생성 작업 기록을 더블클릭하면 해당 결과 폴더를 엽니다.

첫 실행은 사용량 대시보드 대신 **프리셋 생성** 화면에서 시작합니다. 결과 화면 로직은 `ui/results-ui.ps1`, 설정·키·프로젝트 저장은 `ui/project.ps1`에 있습니다. 처리하지 못한 화면 오류는 앱을 닫지 않고 오류 창으로 알립니다.

## v1.3 변경 사항 · 2026-10-16

- **키워드 개편:** 분위기 8개·톤 8개·따뜻한 색감 6개·차가운 색감 6개·팔레트 8개·스타일 8개, 총 44개입니다. 씨드·레퍼런스 화면 모두 같은 목록과 보정 방향을 사용합니다.
- **Windows 실행 복구:** EXE 빌드에서 실제 import 배열 위치를 사용하도록 수정했습니다. 런처가 앱을 열지 않고 즉시 종료하던 문제와 WSH에서 예약어 `enum`을 해석하지 못하던 문제를 해결했습니다. 엔진은 명시적 JScript 호스트로 실행하며 실패 원인을 전달합니다.
- **후보 선별:** 같은 씨드의 보정값 간격을 정규화해 비교하고, 정해진 충실도·변주 예산 안에서 더 멀리 떨어진 후보를 선택합니다. 레퍼런스 추정 기본값도 비교 기준에 포함합니다. 유사 후보를 제외하면 요청 수와 실제 생성 수를 함께 표시하고 manifest에 제외 수를 기록합니다. 사진을 렌더링해 측정한 시각적 유사도는 아닙니다.
- **안전한 저장:** 씨드와 마스크 템플릿을 생성 전 확인하고 내보낼 때 해시를 다시 확인합니다. 읽는 동안 XMP 변경을 막습니다. XMP는 임시 파일에서 값·커브·마스크 보존 검증을 마친 뒤 확정하며 기존 파일을 덮어쓰지 않습니다.
- **진행과 중지:** 사진 분석·검색·수치 추정·씨드 설계·저장 단계를 표시합니다. 중지는 진행 중인 API 응답의 사용량을 기록한 뒤 다음 단계 진입을 막습니다. 응답을 기다리는 동안 버튼 상태가 바뀌며, 창을 닫으면 작업을 종료합니다. 응답을 받지 못한 호출의 사용량은 미확인으로 남습니다.
- **부분 결과 복구:** 파일마다 manifest와 작업 이력을 갱신합니다. 오류나 중지 후에도 저장된 파일 수·후보 정보·폴더 경로가 남고 결과 화면에서 확인할 수 있습니다. 실패/중지 manifest의 `status`는 `failed`/`cancelled`입니다. 실행 중 강제 종료가 발생하면 마지막 체크포인트가 `exporting`으로 남을 수 있습니다.
- **사용량 최적화:** 씨드·레퍼런스 API 기록을 공통 경로로 통합했습니다. 늦게 도착한 대기 상태가 확인된 토큰을 지우지 않습니다. JSONL은 줄 단위로 읽고, 파일·날짜·필터가 같으면 집계 캐시를 재사용합니다. 캐시 쓰기·추론의 행별 값과 합계에 같은 상한을 적용합니다. 일별 CSV에도 캐시 쓰기와 비용 미확인 건수를 포함합니다.

기존 `%LOCALAPPDATA%\PresetSeedLab\usage-events.jsonl`을 그대로 읽으며 별도 이관은 필요하지 않습니다. 현재 프로젝트에서 `PresetSeedLab.exe`를 실행하세요. `app.ps1`과 `ui`, `core`, `assets` 폴더를 비롯한 동봉 파일이 필요합니다.

## 실행

1. 프로젝트 폴더의 **PresetSeedLab.exe**를 실행합니다. 작업을 저장하려면 사이드바의 **프로젝트 → 폴더 지정**으로 작업 폴더를 먼저 정하세요. EXE와 같은 폴더의 `app.ps1`과 `ui`, `core`, `assets` 폴더를 함께 보관하세요. 레퍼런스 모드는 아래의 v1.2 안내를 따르세요.
2. Lightroom 데스크톱에서 내 프리셋을 XMP로 내보낸 뒤 **XMP 추가** 또는 **폴더 추가**로 등록하거나 씨드 카드에 끌어다 놓습니다. 10개 이상을 등록할 수 있고 폴더는 하위 폴더까지 읽습니다. 동일 내용은 중복 등록하지 않습니다.
3. 사용할 씨드와 원하는 키워드를 체크합니다. 키워드는 후보별로 배정되며, 서로 반대인 키워드를 하나의 후보에 동시에 강제하지 않습니다.
4. 기본값은 후보 24개, 충실도 85, 변주 폭 70입니다. 씨드마다 비슷한 수의 후보를 배정합니다. 생성 개수가 선택 씨드 수보다 적으면 일부 씨드만 사용합니다. 선택 순서 편향을 줄이기 위해 생성마다 씨드 순서를 섞습니다.
5. **AI 디렉션**의 **AI 사용** 스위치를 켜고 OpenAI API 키를 입력합니다. 사진은 선택 사항이며 JPG/PNG를 1024px 이하로 축소해서 분석에 사용합니다. 사진을 렌더링하거나 재생성하지 않습니다.
6. 하단의 실행 요약을 확인하고 **프리셋 생성**(Ctrl+Enter)을 누릅니다. 결과 폴더에는 후보별 XMP와 `manifest.json`이 저장됩니다. 원본 씨드는 수정하지 않습니다.
7. Lightroom 데스크톱의 프리셋 가져오기 기능으로 생성된 XMP를 가져와 실제 사진에 적용합니다.

**AI 사용**을 끄면 API 비용 없이 로컬 규칙으로 변주할 수 있습니다. 결과의 `mode`가 `local`로 표시되며, AI 결과로 표시하지 않습니다.

## 씨드 변주 방식

- 후보마다 기준 씨드 하나를 배정합니다. 서로 다른 씨드들을 평균화하지 않습니다.
- 노출·대비·부드러움·온도·틴트·채도·암부·색상·그레인 축을 함께 조절하여 일관된 방향을 만듭니다.
- AI는 축의 방향만 제안합니다. 로컬 엔진이 숫자·허용 범위·충실도 예산을 검증합니다. AI가 XMP나 임의 코드를 직접 작성하지 않습니다.
- 씨드의 커브, 카메라 프로필, LUT 참조, 알 수 없는 설정은 원본 XML에서 보존합니다. 색상 커브와 프로필 자체는 새로 생성하거나 섞지 않습니다.
- 충실도 100에서는 색상 앵커·화이트밸런스를 고정합니다. 밝기·질감 등에는 작은 변화가 남을 수 있습니다. 충실도를 낮추면 HSL/화이트밸런스 등의 변화 폭이 넓어집니다.
- 같은 씨드에서 동일하거나 보정값 간격이 작은 후보를 제외합니다. 변주 폭이 작거나 충실도가 높으면 요청 개수보다 적게 생성할 수 있습니다. 실제 사진의 시각적 차이는 Lightroom에서 확인해야 합니다.
- RAW의 Temperature는 Kelvin 범위, JPG의 Temperature는 상대 범위를 구분합니다.
- 결과 이름, 기준 씨드, 키워드, 변경값, 생성 이유, 랜덤 시드와 API 사용량을 기록합니다.

## 인물·배경 마스크

씨드에 마스크가 있으면 그 구조를 보존합니다. 또는 Lightroom에서 인물·배경 마스크가 포함된 적응형 프리셋을 내보내 변주 설정 카드의 **템플릿 선택**으로 등록할 수 있습니다.

**인물·배경 마스크의 기존 보정값도 변주**를 체크하면 `CorrectionName`에 인물/피사체/배경 또는 Subject/Person/People/Portrait/Background/BG가 포함된 마스크의 기존 로컬 노출·대비·클래리티·채도 값만 변형합니다. 확인하지 못한 이름·형식·필드는 그대로 보존합니다. 새 선택 영역이나 Adobe 내부 바이너리 마스크를 만들어내지 않습니다.

사진마다 선택 영역을 다시 계산하는 일은 Lightroom이 담당합니다. 적응형 마스크 재계산, 템플릿의 형식 호환성, 실제 가져오기는 Windows와 Lightroom에서 별도 확인이 필요합니다. 일반 프리셋에 마스크가 없고 템플릿도 없다면 새 인물·배경 마스크는 추가되지 않습니다.

사용자 지정 프로필이 필요한 씨드는 Lightroom에 해당 프로필이 설치되어 있어야 합니다. 파일에 참조만 있는 프로필/LUT는 이 앱이 복제하지 않습니다.

## API와 비용

- OpenAI Responses API의 Structured Outputs를 사용합니다. 기본 모델 ID는 `gpt-6-luna`이며 접근 권한에 맞게 변경할 수 있습니다.
- 후보 최대 12개씩 설계합니다. 24개는 일반적으로 2회, 60개는 5회 호출입니다. 각 호출에는 해당 후보에 사용되는 씨드의 수치 요약과 선택 사진만 전송합니다.
- API 키는 기본적으로 실행 중 메모리에만 유지합니다. **이 PC에 키 저장**을 켠 경우에만 DPAPI로 암호화해 `api-key.json`에 저장하며, 설정·프로젝트·임시 JSON·결과 파일에는 기록하지 않습니다. 요청은 `store:false`를 사용합니다. 공급자의 데이터 보관 정책은 별개입니다.
- 화면과 manifest의 입력/출력 토큰은 API 응답의 실제 usage입니다. 출력에는 추론 토큰이 포함될 수 있습니다.
- 가격 계산은 Standard 요금 가정입니다(레퍼런스 기능 추가 시 2026-10-16 재확인). Luna는 입력 $0.10/M, 출력 $0.50/M, Sol은 입력 $2/M, 출력 $10/M입니다. 캐시 입력·캐시 쓰기와 알려진 장문 컨텍스트 계수를 반영한 참고값입니다. 세금·지역 요금·향후 가격 변경은 반영하지 않습니다. 알 수 없는 처리 티어는 비용 미확인으로 표시합니다. 알 수 없는 모델은 토큰만 표시합니다.
- 참고로 총 입력 8,000 / 출력 4,000토큰이면 Luna $0.0028, Sol $0.056입니다. 후보 수·사진·추론량에 따라 달라지며 미리 고정된 장당 요금은 아닙니다.
- 앱은 프리셋 생성 전용입니다. Adobe API나 Lightroom 플러그인 연결은 필요하지 않습니다.

## 실행 환경과 검증 범위

Windows 10/11 x64, Windows PowerShell 5.1, .NET Framework의 WPF와 Windows Script Host를 사용합니다. 일반 Windows 설치에 포함된 구성요소이며 Python/Node 설치는 실행에 필요하지 않습니다. 조직에서 PowerShell 또는 Script Host가 차단된 환경은 지원하지 않습니다.

EXE는 함께 제공된 읽을 수 있는 PowerShell 앱을 실행하는 작은 네이티브 런처입니다. PowerShell 실행 정책 우회는 해당 자식 프로세스에만 적용하며 시스템 정책을 변경하지 않습니다. 설치·관리자 권한·레지스트리 변경은 없습니다.

검증한 항목: 실제 JS 변주 엔진의 범위/씨드 배정/중복 제거/AI 응답 검증/WSH 호환 JSON, 테스트용 XMP의 XML 구조, Windows PE 실행파일의 형식·엔트리·DLL import.

**Windows PowerShell 5.1에서 WPF·WSH·가상 API 통합 검사와 실제 EXE 화면 조작(프로젝트 복원·로컬 24개 생성·결과·대시보드) 검사를 통과했습니다. 개인 API 키로 실제 요청하기, Lightroom 가져오기·마스크 재계산·보정 품질 비교는 아직 별도 확인이 필요합니다.**

## v1.1 · 사용량 대시보드

밝은 배경과 블루 포인트, 카드와 사이드바를 사용하며 화면을 사용량 대시보드 / 프리셋 생성 / 생성 결과로 구분했습니다.

- 최근 7일·30일·90일·전체 기간 및 모델 필터.
- 입력·출력 토큰, 캐시 입력, 추론 토큰. 추론은 출력의 일부이며 총 토큰에 다시 더하지 않습니다.
- API 호출 수, 프리셋 생성 작업 수와 실제로 저장된 프리셋 개수.
- 일별 입력/출력 누적 막대 차트, API 호출 수 및 생성 작업 수 차트. 긴 기간은 주별로 묶고 CSV에는 정확한 일별 값을 남깁니다.
- 모델별 토큰·예상 비용과 전기간 대비 토큰 증감.
- 호출별 기록, 실패·미완료·중지 상태와 CSV 내보내기.

API 응답을 받은 즉시 사용량을 저장합니다. 이후 JSON 파싱이나 XMP 내보내기가 실패해도 해당 호출의 토큰은 기록에 남습니다. 응답 미수신 호출은 미확인으로 남기고 알려진 토큰·비용 합계에서 제외합니다. 토큰이 확인되어도 모델/처리 티어의 가격을 모르면 비용은 미확인입니다.

이력은 `%LOCALAPPDATA%\PresetSeedLab\usage-events.jsonl`에 추가 방식으로 저장되며 앱을 재시작하거나 프로그램 폴더를 옮겨도 유지됩니다. 키·프롬프트·원본 사진을 사용 기록에 저장하지 않습니다. 같은 호출의 대기/응답 상태가 여러 번 저장되어도 대시보드에서는 하나로 집계합니다. 출력 프리셋의 저장 폴더는 생성 작업 기록에 남습니다.

이 버전부터 앱에서 실행한 작업을 추적합니다. 다른 앱에서 사용한 동일 API 키의 사용량, 이 버전 이전의 실행 기록, 공급자 청구서는 자동으로 가져오지 않습니다. 날짜는 실행 PC의 현지 날짜 기준입니다.

추가 검증: `node tests/usage.test.js` (16개 테스트). 기간 경계, 재시작 시 읽는 이벤트 재구성, 중복 제거, 실패 호출, 모델 분리, 주별 합계 보존, 캐시 요금 계산을 검사합니다. Windows 검증 도구는 별도 임시 기록 폴더를 사용하므로 샘플 사용량이 실제 대시보드에 섞이지 않습니다.

## v1.2 · 레퍼런스로 만들기

씨드 XMP가 없어도 쓸 수 있는 별도 생성 모드입니다. 사진의 원래 프리셋을 찾아내거나 정확한 원본 수치를 복원하는 기능은 아닙니다. AI가 사진의 색감·톤·질감을 관찰하고, 그 스타일을 재현할 보정값을 추정합니다. 실제 Lightroom 렌더링과 픽셀 차이를 반복 최적화하는 기능은 포함하지 않습니다.

1. 사이드바의 **레퍼런스로 만들기**를 열고 JPG/PNG 1~24장을 추가합니다. 같은 내용의 파일은 중복 등록하지 않습니다.
2. **여러 장의 공통 스타일** 또는 **사진별 개별 스타일**을 선택합니다. 개별 모드의 총 생성 개수는 사진 수 이상이어야 합니다.
3. API 키와 이미지 입력·구조화 출력을 지원하는 모델을 지정합니다. 기본값은 `gpt-6-luna`입니다. 검색을 켜면 웹 검색도 지원해야 합니다.
4. **웹에서 보정 방법 검색**은 분석한 스타일을 재현할 Adobe 공식 보정 자료를 검색합니다. 사진의 원출처·작가·원본 프리셋을 찾는 역이미지 검색이 아닙니다. 검색 단계에는 색감·톤 설명만 전달하고 이미지나 파일 경로는 넣지 않습니다. 검색을 끄면 사진 분석만으로 추정합니다. 검색 요청이 실패하면 몰래 검색 없는 결과로 바꾸지 않고 오류로 표시합니다.
5. 선택 사항인 **적용할 원본 사진**에는 보정 전 JPG/PNG를 넣습니다. 있으면 그 사진에서 목표 스타일로 가는 보정값을 추정하며, 없으면 범용 시작점을 만듭니다. RAW 자체는 읽지 않으므로 RAW 작업에서는 보정 전 미리보기 JPG를 사용하세요.
6. 아래 안내대로 인물·배경 템플릿을 등록하거나, 전체 보정만 원하면 인물·배경 체크를 모두 해제합니다.
7. 생성 개수·충실도·변주 폭과 키워드를 정하고 생성합니다. 각 스타일의 첫 후보는 추정 기본값이며 나머지는 로컬 엔진의 변주입니다. 기본값 12개 후보는 API 호출 12회를 의미하지 않습니다.

추정 범위는 노출, 대비, 하이라이트·섀도·화이트·블랙, 텍스처, 클래리티, 디헤이즈, 비브런스·채도, 그레인, HSL 8색, 분할 토닝, RGB 및 채널 커브입니다. 화이트밸런스의 RAW/JPG 단위 차이를 피하기 위해 레퍼런스 모드는 전역 Temperature/Tint와 카메라 프로필을 덮어쓰지 않습니다. 따뜻함·차가움은 HSL·토닝·채널 커브로 근사합니다. 조명, 배경 소재, 메이크업을 보정 효과로 잘못 추정할 수 있으며, 확신도 표시는 AI의 정성적 해석이지 측정된 일치율이 아닙니다.

### 인물·배경 템플릿 준비 · 한 번만

1. Lightroom 클라우드 데스크톱에서 아무 인물 사진을 열고 **Select Subject**와 **Select Background** 마스크를 각각 만듭니다. 이름은 인물/배경 또는 Subject/Background로 지정하면 편리합니다.
2. 해당 마스킹을 포함해 사용자 프리셋을 저장하고, 프리셋을 우클릭해 **Export**로 XMP를 내보냅니다. 마스크가 저장됐는지 Lightroom에서 확인하세요.
3. 앱의 **AI 마스크 템플릿**에서 XMP를 열고 인물과 배경에 사용할 그룹을 각각 선택합니다. 같은 그룹을 두 영역에 동시에 쓰는 것은 막습니다. 선택한 그룹에 AI 선택 영역 `Mask/Image`가 없으면 다른 사진용 자동 마스크로 취급하지 않고 오류로 안내합니다.

AI는 인물·배경의 노출, 대비, 하이라이트·섀도·화이트·블랙, 색온도·틴트, 채도, 텍스처·클래리티·디헤이즈를 각각 설계합니다. 내보낼 때 선택한 두 그룹만 복사하며 기존 Local 계열 보정(로컬 커브 포함)은 제거한 뒤 새 값을 씁니다. 템플릿의 전역 보정은 가져오지 않습니다. 사용자에게는 노출을 EV 단위로 보여주고, XMP에는 EV/4로 저장합니다(예: +0.30 EV → `LocalExposure2012=0.075`). 다른 로컬 슬라이더는 UI/100으로 변환합니다(예: 색온도 +12 → `LocalTemperature=0.12`). 기존 씨드 마스크 변주의 분수 단위도 이번 버전에서 수정했습니다.

선택 영역·마스크 ID·바이너리 데이터는 생성하거나 수정하지 않습니다. 따라서 템플릿 없이 새 Adobe AI 선택 영역을 만들 수는 없습니다. 실제 사진에 맞는 선택 영역 재계산은 Lightroom에서 이루어지며, 적용 후 영역과 경계를 확인하세요. 템플릿 파일이 생성 도중 바뀌면 내보내기를 중단합니다.

### 호출 수·사용량·결과

- 레퍼런스 R장은 4장씩 묶어 관찰합니다: `ceil(R/4)` API 호출.
- 보정 자료 검색을 켜면 1 API 호출을 더 사용합니다. 한 응답의 내장 도구 호출은 최대 2회이며, 청구되는 `search` 동작만 집계합니다. 페이지 열기는 검색 횟수에 더하지 않습니다.
- 수치 추정 단계에서는 관찰 요약과 관찰 단계에서 사용한 1024px 이하의 레퍼런스 이미지, 선택한 원본 이미지를 함께 확인합니다. 공통 모드 1회, 개별 모드 `ceil(R/4)` 호출입니다. 예를 들어 4장·공통·검색 켬은 보통 3 API 호출입니다. 변주 개수는 추가 API 호출을 만들지 않습니다.
- API가 반환한 실제 입력/출력 토큰에 이미지 분석 토큰이 포함됩니다. 검색 콘텐츠 토큰도 모델 요금에 따르며, 별도 검색 호출료는 검색당 $0.01입니다. 예를 들어 전체 입력 8,000/출력 4,000과 검색 1회라면 Luna 기준 약 $0.0128입니다. 실제 토큰은 사진 수·추론·검색 결과에 따라 달라집니다.
- 대시보드와 CSV에 사진 분석 / 보정 검색 / 보정 추정 단계를 기록하며 검색 횟수와 비용을 합산합니다. 실패한 후속 단계 때문에 앞서 사용한 토큰이 사라지지 않습니다.
- 결과 폴더에는 XMP, 관찰·추정 수치·확신도·한계·사용량을 담은 `manifest.json`, 검색 요약·실제 API가 반환한 출처 URL을 담은 `analysis.txt`가 생성됩니다. 원본 사진과 API 키는 결과나 사용량 로그에 저장하지 않습니다. manifest에는 구분용 파일명만 남습니다.

추가 소스: `core/reference.js`(JSON 계약·검증·변주·마스크 단위 변환), `core/reference.ps1`(분석 흐름·XMP 출력), `ui/reference-ui.ps1`(화면 연결), `core/api.ps1`(사용량 선기록), `assets/reference-base.xmp`(중립 프리셋 골격).

로컬 로직 검증: `node tests/engine.test.js`, `node tests/usage.test.js`, `node tests/reference.test.js`. 현재 총 70개입니다. 최대 24개 레퍼런스의 배정, AI 수치·커브 복구와 잘못된 구조 거절, 1,600개 채널 커브의 범위·순서·반복 보정 안정성, 로컬 마스크 단위, 기준 후보 보존, 중복 제거, 검색 요금·출처·이력, 레거시 JS 호환성을 검사합니다.

`tests\ValidateOnWindows.cmd`에는 WPF 로드, 테스트용 API 응답을 이용한 레퍼런스 전체 흐름, 인물·배경 XMP 출력·선택 영역 보존·사용량 기록 검사를 추가했습니다. 외부 API를 호출하지 않으며, 테스트 마스크는 임시 데이터입니다. v1.3에서는 이 Windows 통합 검사를 실행했고, 변경된 입력 거절·실패 시 과금 기록·응답 중 취소·저장 중 취소·부분 manifest·집계 캐시 회귀 검사도 추가했습니다. 실제 API와 Lightroom 마스크 재계산·스타일 재현 품질은 실기 확인이 필요합니다.
