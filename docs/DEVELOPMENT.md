# 개발 안내

사용법은 [README](../README.md), 검증 결과는 [validation.json](validation.json)을 참고하세요. 변경 이력은 Git 커밋에 남깁니다.

## 파일 구성

| 위치 | 역할 |
| --- | --- |
| `PresetSeedLab.exe`, `app.ps1` | 네이티브 런처, 앱 진입점과 백그라운드 작업 |
| `ui/` | WPF XAML, 화면 연결, 프로젝트·설정·키 저장 |
| `core/` | ES5 수치 엔진, XMP 입출력, API·사용량·작업 상태 처리 |
| `assets/` | 키워드 60개와 레퍼런스용 중립 XMP |
| `tests/` | Node 로직 검사, Windows 통합·UI 검사, 가상 입력·응답 |
| `tools/` | 키워드·테스트 입력 재생성, 런처 빌드 |
| `docs/` | 개발 안내와 검증 기록 |

런처는 같은 폴더의 `app.ps1`을 실행합니다. PowerShell 실행 정책은 자식 프로세스에만 적용합니다. 앱과 엔진은 Windows PowerShell 5.1·Windows Script Host에서 동작해야 하므로 **PS1 파일의 UTF-8 BOM과 JavaScript의 ES5 호환성을 유지**하세요. 앱 실행에는 개발 도구가 필요하지 않습니다.

## 검사와 빌드

저장소 루트에서 실행합니다. Windows 검사는 Windows 터미널에서 실행하세요.

| 명령 | 확인하는 내용 |
| --- | --- |
| `npm test` | 씨드 14개·사용량 16개·레퍼런스 24개·믹스매치 24개, 총 78개 로직 검사 |
| `tests\ValidateOnWindows.cmd` 또는 `npm run test:windows` | 실제 PowerShell/WPF/WSH, XMP 출력, 가상 API, 실패·취소·부분 결과, 마스크·프로필 보존 |
| `powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-ui-smoke.ps1` | 실제 EXE 화면 조작, 씨드 24개와 믹스매치 1개 생성, 키워드·비율·결과·대시보드 |
| `powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-mix-ui.ps1` | 랜덤 전체·항목별 설정, 후보별 기준, 로컬 3개 생성, 프로젝트·결과 재시작 복원 |
| `powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows-adaptive-ui.ps1` | 템플릿 없는 마스크, AI를 끈 생성, 옵션 복원, 이전 템플릿 프로젝트 호환 |
| `node tools/build_assets.js --keywords-only` | 엔진 정의에서 키워드 목록만 갱신 |
| `npm run build:assets` | 키워드와 테스트용 가상 XMP 12개 재생성 |
| `npm run build:launcher` | Python 3와 GNU gcc/ld/nm으로 x64 EXE 런처 빌드 |

Node.js는 로직 검사·에셋 생성에, Python과 GNU 도구는 런처 빌드에 사용합니다. 앱의 PS1·XAML 변경에는 런처 재빌드가 필요하지 않습니다. Windows 검사는 임시 사용량·출력 폴더와 가짜 키·응답을 사용하며 외부 API를 호출하지 않습니다. EXE 조작 검사 중에는 테스트 창이 표시됩니다.

## 생성 규칙

- **씨드:** 후보마다 기준 하나를 배정합니다. 커브·프로필·LUT 참조·지원하지 않는 XML 설정은 보존하며, 허용한 수치 축만 충실도·변주 예산 안에서 바꿉니다. RAW의 Kelvin과 JPG의 상대 화이트밸런스 단위를 구분합니다. 같은 씨드의 유사 후보는 정규화한 보정값 간격으로 선별합니다.
- **믹스매치:** 허용된 톤·색감·질감 슬라이더와 커브만 혼합합니다. 일부 입력에 없는 슬라이더는 중립값을 사용하고, 모든 참여 입력과 기준에 없는 필드는 만들지 않습니다. 색상 각도는 채도를 가중치로 원형 평균합니다. 여러 커브는 X=0/64/128/192/255에서 보간하고, 단일 출처는 기존 좌표를 사용합니다.
- **랜덤:** 비율이 0보다 큰 입력만 참여합니다. 저장된 랜덤 시드로 AI 사용 여부와 무관한 초안을 재현합니다. 후보별 기준 ID로 XMP를 내보내며, 고정 항목과 기준은 AI가 바꾸지 않습니다. 랜덤 항목의 AI 추천 반영률은 `variation / 100 * 0.2`입니다. 최종 비율과 조정 전 `draftRatios`를 기록합니다.
- **레퍼런스:** 사진 관찰 → 선택적 자료 검색 → 수치 추정 → 로컬 변주 순서입니다. 전역 Temperature/Tint·프로필은 새로 쓰지 않습니다. 로컬 노출은 EV/4, 다른 로컬 슬라이더는 UI/100으로 XMP에 저장합니다.
- **수치 복구:** 레퍼런스의 유한한 범위 초과 값은 제한하고, 5점 커브의 역순 Y 구간은 인접 평균으로 정리해 정수화합니다. 평평해진 커브는 직선으로 대체합니다. 복구는 `repairs`와 분석 내역에 기록하며 API를 추가 호출하지 않습니다. 누락·비수치·잘못된 구조는 거절합니다.
- **마스크:** 자동 선택은 새 ID와 `Mask/Image`, subtype 1, 피사체/배경 반전 여부를 기록합니다. 사진별 픽셀 선택 영역은 Lightroom이 계산합니다. 기존 마스크 데이터는 불투명 데이터로 취급하며 임의로 생성하지 않습니다. 레퍼런스의 선택형 템플릿은 지정한 그룹의 선택 영역을 보존하고 Local 보정값을 새 레시피로 교체합니다.
- **입력·저장:** 생성 전 입력 해시와 사진 디코딩을 확인합니다. 출력은 임시 XMP를 다시 읽어 값·구조를 검증한 뒤 확정합니다. 후보마다 manifest를 갱신해 오류·취소 시 부분 결과를 복원합니다.

이 검사는 수치·파일·작업 흐름을 검증합니다. Lightroom 렌더링을 재현하거나 사진의 시각적 유사도를 측정하지 않습니다.

## API와 로컬 저장

AI는 구조화한 수치 계획만 반환하며, 호스트가 허용 범위와 형식을 검증합니다. 요청은 `store:false`를 사용합니다. 응답을 받은 즉시 사용량을 기록한 뒤 내용을 파싱하므로, 잘못된 응답이나 후속 내보내기 실패도 확인된 사용량을 지우지 않습니다.

| 작업 | 일반적인 API 호출 수 |
| --- | --- |
| 씨드 AI 변주 | 후보 12개마다 1회 |
| AI 믹스매치 | 후보 6개마다 1회 |
| 레퍼런스 관찰 | 사진 4장마다 1회 |
| 레퍼런스 수치 추정 | 공통 스타일 1회, 사진별 스타일은 4장마다 1회 |
| 레퍼런스 자료 검색 | 켜면 요청 1회 추가; 내장 검색 동작 비용은 별도 집계 |

레퍼런스 변주 개수는 분석 호출 수를 늘리지 않습니다. 검색에는 스타일 설명을 전달하고, 수치 추정에는 관찰 때 보관한 축소 이미지와 선택한 원본 사진을 사용합니다. 이미지 처리·JSON·인증·접근 권한·네트워크 실패는 자동 재시도하지 않습니다.

`%LOCALAPPDATA%\PresetSeedLab`에 `settings.json`, 선택적으로 암호화한 `api-key.json`, 추가 방식의 `usage-events.jsonl`을 저장합니다. 테스트에서는 `SEEDLAB_TEST_USAGE_DIR`로 격리합니다. 프로젝트 값이 전역 설정보다 우선하며, 키는 프로젝트·manifest·사용량 로그에 기록하지 않습니다. 미확인 사용량·가격은 0으로 확정하지 않고 미확인 상태로 남깁니다.
